# 百炼智能路由 (dsh-bailian-auto-router)

决策模型驱动的阿里云百炼路由插件:在 DSH 模型选择器中注册虚拟模型
`bailian-auto`(显示名「百炼智能路由」)。选择它之后,每次请求都会先在**请求前**由决策模型
分析输入,再路由到最合适的百炼执行模型。

## 功能

- **请求前主动决策**(区别于仅失败后被动切换的方案):默认决策模型
  `deepseek-v4.1-flash-1017` 分析输入的模态(文本/图片/代码)与任务类型
  (写作、推理、翻译、代码、图片分析),输出
  `{"selected_model": "...", "reasoning": "..."}`;无效答案自动回落到启发式排序。
- **执行模型池**:首次安装自动从百炼 `/models` 拉取列表(本机实测同步 182 个模型),
  与内置 40+ 模型目录、用户自定义清单合并;额度/冷却状态持久化在
  `~/.dsh/bailian-auto-router/state.json`(不轮询额度接口)。
- **路由规则**:图片分析只从视觉模型(qwen-vl / qwen3.8-max-0902 / omni 系列)中选择;
  中文写作优先 `glm-5.2`、`qwen3.8-max-0902`;复杂逻辑/代码优先 `deepseek-v4-pro`、
  `qwen3.8-max-0902`;翻译优先专用 `qwen-mt-*`。
- **额度感知**:路由前检查本地冷却;额度/限流失败自动切下一个可用模型并更新本地状态
  (额度冷却 30 分钟、限流冷却 120 秒,可配)。
- **容灾降级**:决策模型超时/失败直接用回退模型;执行模型失败(429、额度耗尽、网络错误)
  在**尚未输出任何内容前**静默切换;一旦已输出内容则不再切换,直接报错,避免重复输出。
- **本地额度/冷却/连败计数**记录。

## 负载均衡(同类模型按 token 轮转)

同一个任务不会永远打在最强的那个模型上。路由先在账号模型池里按任务排序,再取前 N 个
(`balanceWindow`,默认 6)作为"同类候选",在这些模型之间按**近期 token 消耗**轮转:
消耗最少且最久没被用过的优先。实测同一 code 请求连续三次 →
`qwen3.8-max-0902 → qwen3.8-2.4t-a95b → deepseek-v4.1-flash-1017`。

- 额度/限流冷却中的模型不参与轮转,只作为回退链尾部;
- `balanceStrategy=quality` 可关闭轮转,始终用最优模型;
- `balanceBand>0` 可加分数保护带,避免把旗舰和低价小模型混在一个轮转集里;
- 用量按任务桶统计并随窗口(`balanceWindowHours`,默认 24h)自然衰减。

## 思考档位随任务复杂度自动切换

虚拟模型在选择器里提供 `auto / off / low / medium / high / max` 六档,默认 `auto`。
`auto` 会从输入长度、代码密度、推理类词汇命中数、已执行工具步数估算复杂度(0–100),
再映射到档位:trivial→off、simple→low、normal→medium、complex→high、deep→max。
选中具体档位则会覆盖自动策略。下游不支持该参数的模型会被自动记住并跳过参数重试,
不会让整轮对话失败。

## 媒体端点(图像生成)

`/models` 里 TTS、ASR、向量化、重排、图像生成等端点**不再被无差别丢弃**,而是按能力分类:

| 能力 | 处理方式 |
|---|---|
| 图像生成 | **可直接路由**。说"画一张…/生成图片/配图"时,路由器调用 `POST /images/generations`,把图片保存到工作区 `.dsh-media/`,回复里给出 Markdown 图片链接。本期账号实测 12 个图像模型可用 |
| 语音合成 / 语音识别 | 该网关 HTTP 面不提供(实测 `/audio/speech` 404、chat 带 `voice` 报 400),因此保留在清单里但不参与路由,面板显示数量 |
| 向量化 / 重排 | 不是对话能力,保留在清单里供检索类用途,不参与对话路由 |
| 视频生成 | 若账号存在视频模型会被识别并列出;当前插件只接入了图像生成调用端,视频接口未接入,因此不会自动调用 |
| 实时流(realtime/livetranslate) | 需要 WebSocket 双向流,不适用于普通对话 |

### 视频意图:零 token 短路回复

识别到"生成视频/做个小视频/动画短片"这类意图时,路由器**不调用任何模型**,直接回复:

> 本账号没有视频生成模型(共 182 个模型,其中视频模型 0 个),无法直接产出视频。
> 可选方案:1) 图像 + 合成(短片合成另行安排,需你确认)… 2) 换一个开通了视频模型的账号 … 3) 你提供素材 …
> 要我按方案 1 继续吗?回复「继续」即可。

这样既不会把请求当普通对话丢给聊天模型(实测会白烧 1 万 token 写脚本),也把选择权留给用户。
"讨论视频"(如"视频用什么编码")不会被误判为生成意图;**带产物名词的请求也不会被误短路**:
"生成一个视频脚本""视频分镜脚本""生成视频提示词""做一个动画演示 PPT""剪辑这段视频"都会降级为
对话或图像;只有"生成/制作/合成 + 视频/短片/动画"且不含排除词时才短路。

### 会话粘模型:同一会话固定首选模型

同一 `sessionId` 的请求优先沿用上一轮的执行模型,避免连续轮换打掉 provider 的 prompt cache
与 tool-call 格式稳定性:

- 绑定存本地状态,TTL 24h、上限 200 条,换账号(端点/凭据变化)自动清空;
- 每 `sessionTurnLimit` 轮(默认 8)允许重选一次;上下文接近绑定模型上下文窗口时也会解绑重选,重选仍走均衡带;
- 绑定模型进入冷却、不可用或报错时,照常静默切换下一个候选,并解除该会话绑定;
- 子调用/headless 不带 `sessionId` 时,不写绑定,降级为请求级轮转。

## 换阿里云账号无需改配置

插件不绑定任何特定账号、端点或模型清单:

- **模型池来自账号本身**:每次请求的可选模型是当前端点 `GET /models` 的返回(本机实测 182 个 →
  可对话 140 个,另有 42 个 TTS/ASR/向量化/重排/图像生成等非对话端点被自动排除)。
  内置目录只提供元数据(名称、视觉能力、上下文),**不影响池的成员资格**。
- **换端点或凭据引用即自动重置**:本地状态按 `baseURL|凭据引用` 记录作用域,切号后旧账号的
  模型池与额度冷却自动清空,不会误用已不存在的模型或复活旧冷却。
- **配置的决策/回退模型不存在时自动替代**:新账号若不提供 `deepseek-v4.1-flash-1017`,
  路由会自动挑一个该账号真实存在的快模型做决策模型、一个通用模型做回退,并在面板明确提示
  (原配置保留不变,换回原账号即自动恢复)。
- **一键切号**:面板「阿里云连接」列出本 profile 中所有阿里云兼容 provider,点「切到这个账号」
  即切换端点+凭据并重新同步模型池。

## 零配置开始

- **连接自动沿用**:若本 profile 已有指向阿里云的 OpenAI 兼容 provider
  (如 `llm-pi-ai` 下的 `bailian`),插件会自动沿用它的 `baseURL` 与凭据引用,
  无需重复填写;显式填写 `baseURL` 则永远优先。
- **凭据回退链**:`BAILIAN_API_KEY` → `DASHSCOPE_API_KEY` → `ALIYUN_API_KEY`,
  先解析 DSH 凭据服务,再读启动环境变量。
- **零运行时依赖**:包内不依赖任何第三方 npm 包(zod 已移除,手写边界解析器),
  因此从任意目录安装都不会因缺 `node_modules` 而激活失败。

## 配置面板

**插件(Plugins)页 → dsh-bailian-auto-router** 配置区可编辑:决策模型、回退模型、
决策超时、最大尝试次数、额度/限流冷却、各任务类型候选列表、自定义模型池(JSON)。

状态区展示:生效接口与凭据(含"已沿用哪个 provider")、模型池来源(内置/同步/自定义)、
每个模型的本地冷却状态(启发式,非真实配额;可用/冷却剩余时间)、连败与调用计数、最近 50 条路由决策
(任务类型、决策来源、尝试链、原因)。

另在 **设置 → 模型** 底部有一张状态小卡片。

## 真实端点验证

`npm run test:live` 使用本机凭据与 endpoint 跑通完整链路(离线单测见 `npm test`):
虚拟模型注册、182 个模型同步、写作→`glm-5.2`、代码/通用→`deepseek-v4.1-flash-1017`,
以及 usage 计费块与本地额度记账。
